What is different for articles:
- Every article becomes a localized page: add `app/[lang]/<route>/page.tsx` for each article you own, rendering
  the same page for `lang` with `generateMetadata` via `langMeta('/<route>', lang, copy.meta, {...})` (keep the
  article's openGraph type 'article', images and other extras the English page has) and its JSON-LD with
  `inLanguage: HTML_LANG[lang]`. The English page.tsx gains `alternates.languages: langAlternates('/<route>')`.
  The cleanest shape is to move the English page body into a shared server component
  (e.g. `<route>/Article.tsx` taking `{ lang }`) that both page.tsx files render; the English page.tsx keeps
  its `metadata` export.
- Use the large pattern (`<route>/_copy/en.tsx` + `index.ts` with `load<X>Copy(lang)`). Client widgets get
  their strings as props from the server page, or from a small context provider in the article, never by
  importing every language.
- Copy covers prose, headings, captions, figure alt text, chapter-rail labels, widget labels and states,
  button text, aria-labels, the back link, ArticleLinks labels, metadata and JSON-LD prose.
- Keep these in English and out of the copy (say so in your report): code listings and prompts shown as
  code (they are real artifacts), screens that reproduce a real device's firmware UI pixel for pixel,
  sensor/log readouts that imitate real output, file names, and anything generated by another project
  (app/waterslop/chapter/ is exported from the WaterSlop project: do not touch it).
- Links: internal links to ANY page of the site (articles too, they are localized now) are written as the
  English path in copy JSX (href="/pip"); code that renders links uses `localize(href, lang)`. Note that
  `localize` only prefixes paths listed in lib/i18n.ts LOCALIZED, which the lead updates at the end, so
  during your work /ja links to articles still come out unprefixed. That is expected.
- Shared components (ArticleRecommendations, ArticleLinks, ArticleLightbox, ArticleScrollSpy, ProjectPeek,
  components/peeks/*) belong to one agent only: if your article passes text into them, pass already
  translated strings from your copy.
- Article pages often have canvas/WebGL widgets that draw text. Captions and labels drawn on a canvas are
  copy too (pass them in as props); keep units, symbols, axis numbers and code identifiers as they are.
- Your before/after diff must be identical for the English page, and /ja/<route> must render (still in
  English) with no console errors and no hydration warnings.
